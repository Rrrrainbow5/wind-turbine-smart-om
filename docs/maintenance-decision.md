# 基础维护决策规则

## 目的

第一版维护决策器用于跑通“AI 风险结果到工程动作”的 P0 闭环。它不是经过真实风场验证的全局优化模型，也不输出未经证实的维修成本或风险下降比例。

## 输入

- `failure_risk`
- `warning_level`
- 人员是否可用
- 维护窗口是否可用
- 决策条件的数据来源类型

风险数据可以随请求提供，也可以读取数据库中该部件最新的 AI 结果。

## 动作

- `CONTINUE_MONITORING`：继续监测
- `SCHEDULE_INSPECTION`：安排检查
- `SCHEDULE_MAINTENANCE`：安排维护

## 当前规则

- 高风险：`failure_risk >= 0.75` 或 `warning_level = HIGH`
- 中风险：`failure_risk >= 0.45` 或 `warning_level = MEDIUM`
- 高风险且人员、维护窗口均可用：安排维护
- 高风险但维护条件不完整：执行当前可行动作，并标记需要重新规划
- 中风险且人员可用：安排检查
- 其余情况：继续监测

这些阈值属于第一版工程规则，不应在论文或答辩中表述为真实风场标准。后续由 A、B、D 根据 CARE 实验结果、可追溯资料和工程约束共同调整。

## 后续升级条件

只有在成本、工时、资源、天气窗口和风险模型的定义获得可靠依据后，才引入带量纲的目标函数和多风机调度优化。
