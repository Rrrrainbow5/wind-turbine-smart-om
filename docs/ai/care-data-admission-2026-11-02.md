# CARE 数据准入审查：按独立机组补齐故障类别

运行 `python -m ai.care_coverage_audit --data-root D:/工创赛/care-data --output models/care-coverage-audit/report.json` 可复核事件与传感器映射。此报告只审查事件元数据，不是模型验证。完整事件和排除项见 JSON。

| 清晰可用的事件类别 | 独立机组 | 当前决定 |
|---|---:|---|
| 齿轮箱本体 | 1 | 不足以按机组留出训练并验证该类 |
| 齿轮箱轴承 | 1 | 不足；不得与转子轴承混为同一零件 |
| 发电机轴承 | 2 | 可试验，仍需检查标签及跨机组指标 |
| 转子/主轴承（B 场上层类别） | 3 | 可做同场上层事件试验，不可直接当齿轮箱轴承 |
| 液压（A 场） | 4 | 可试验，现有严格留出表现仍弱 |
| 变压器温升（A/B） | 4 | 可试验，A/B 通道与工况需要分别核验 |
| 变桨系统事件（C 场） | 4 | 新增候选，但不是同一具体失效形式；C 场原始 CSV 尚未提取 |
| 变流器事件、齿轮油泵联轴器事件（C 场） | 各 1 | 仅事件参考，不可宣称跨机组识别 |

Wind Farm C 的事件元数据已在本地，压缩包中有 59 个原始事件 CSV，解压约 17.8 GB。19 个描述混合故障、原因未明或无法确定单一类别的异常事件被排除，不能凭关键词自动标成确定故障。正常事件共 50 个，跨三场覆盖 36 台独立机组；但仅有正常样本并不能弥补故障类独立机组不足。

统一字段必须按 `feature_description.csv` 的含义和单位映射，不能仅凭 `sensor_编号` 相同。A/B 的发电机轴承温度与 C 的转子轴承温度是不同安装位置，审查脚本分开登记；不能强制当成相同通道。CARE 提供的是十分钟聚合 SCADA，不提供可直接推断齿轮啮合特征频率的高频振动波形。

## 下一轮重训的准入门槛

1. 取得齿轮箱本体、齿轮箱轴承等单机组类别的其他独立机组、明确时间段、部件和故障确认依据。不能用同机组更多窗口代替独立机组。
2. 对 C 场变桨候选先核验六个事件的故障起止时间及多个失效形式是否可合并为“变桨系统异常”，提取相关原始事件 CSV 与同机组正常基线。不要将其并入原六分类冒充同一任务的提升。
3. 生成带版本的统一字段清单，记录来源传感器、单位、安装位置、缺失率；训练折内拟合填补和标准化。
4. 以完整物理机组作为外层留出组，并在训练折内选参。逐类报告 precision、recall、F1、support、混淆矩阵、缺类折和拒识覆盖率。
5. 只有独立验证达标、模型权重和训练报告一致，才替换网页评估和登记可用模型。此前页面保持历史案例回放与实验边界。
