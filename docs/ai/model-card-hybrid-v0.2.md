# Hybrid diagnosis model card v0.2

## Intended use

Research and traceable diagnostic integration for one `sample_id`. A result is a risk score unless calibration evidence supports probability language.

## Data boundaries

CARE Version 6 is aggregate SCADA data. It must not be rendered as measured high-frequency spectra. Raw waveform examples generated by the B simulator are labelled `SIMULATED` and include a random seed.

The Paderborn Bearing Data Center subset is registered as `EXTERNAL_PUBLIC` under CC BY-NC 4.0. The current local subset contains synchronized 64 kHz vibration and two-phase motor-current waveforms for `K001` (healthy), `KA01` (outer-ring damage), and `KI01` (inner-ring damage). Every source file has a stable `sample_id` and SHA-256 in `docs/data/signal-sample-manifest.csv`. The source MAT files leave the waveform `Unit` fields empty, so the adapter reports `source_unit_unspecified` instead of inventing units.

## Evaluation gate

Train/validation/test groups must be separated by turbine, event and time. Required reports are Macro-F1, per-class precision/recall/F1, confusion matrix, PR/ROC, ECE, Brier and branch ablations. No score is promoted to final diagnosis until these reports exist.

The repository now provides `ai.models.evaluate_hybrid_model` to produce this report from a
labelled dataset. It uses a turbine/event/timestamp grouped holdout, records the random seed and
sample IDs, and reports the full hybrid result, every single branch, and leave-one-branch-out
ablations. Scores produced from simulated fixtures are software tests only and must not be quoted
as field-performance evidence.

## Implemented baseline

The current executable contract has three inputs (engineering statistics, resampled raw signals,
and STFT-derived features) and quality-weighted gated fusion. Its lightweight NumPy heads verify
the end-to-end contract without claiming to be XGBoost, 1D-CNN/TCN, or a time-frequency CNN.
Predictions include all class scores, confidence, entropy uncertainty, gate weights, model version,
and the unchanged `sample_id`.

## Known limitations

The current repository has no verified high-rate CARE waveform archive or approved bearing geometry mapping. Consequently, feature-frequency formulas can be returned without bearing-defect Hz values. The local Paderborn subset is labelled but contains only one physical bearing per class; repeated runs from one bearing cannot support a credible cross-bearing generalization claim. The simulator uses illustrative fault-specific periodic patterns and shared severity parameters; it is not a validated physical model or field evidence. The fixed JSON example has `model.status = NOT_INFERRED` and contains no AI diagnosis.

Reproduce the C-facing fixture with `python -m ai.signal_pipeline.example --output examples/signal-analysis-result-v0.2.json`.
