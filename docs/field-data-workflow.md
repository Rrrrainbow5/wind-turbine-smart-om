# 风场接口工作流

接口模式使用后端机组状态和已保存的诊断数据包，演示参数不参与现场诊断。

1. 采集系统提交 `signal-analysis.v2` 到 `POST /api/diagnosis/analyze`，也可以在网页“风场数据接入”上传同协议 JSON。
2. 数据包必须包含已存在的 `turbine_id`、`component_id`、唯一 `sample_id`、通道来源、处理过程和已注册模型的结果。服务端校验，不允许将任意模型名称当成有效推理。
3. 点击同步或上传成功后，读取机组最新诊断。仪表盘、信号依据、部件定位和维护入口使用该记录；维护请求带上 `source_sample_id` 和 `source_diagnosis_id`。
4. 通用轴承分类不能确定轴承安装位置。没有明确对应的 CAD 部件时，不使用叶片或其他轴承代替高亮。
5. 维护执行为人工记录，不能证明物理维修成功。采集端向 `POST /api/retests` 提交 `record_id`、`observed_at`、`health_index`、`failure_risk`、`conclusion` 和真实来源 `data_origin`，再点击“同步现场复测结果”查看。没有结果则保持待复测，不清除故障。

## 当前能力边界

`/api/diagnosis/analyze` 接收并保存诊断结果，不负责加载训练权重后推理。原始波形上传可以计算信号特征，但不能由此声称已完成现场 AI 诊断。当前模型目录没有已部署的 REAL 来源诊断模型；真实风场数据的自动诊断还需要部署训练权重、适配通道及采样率、注册模型，并验证现场适用性。修改来源标签不能替代这些步骤。

实验数据查询、原始信号分析保留为独立辅助入口，不覆盖现场机组状态。接口模式不再为 WT02 无条件填入固定 B53 故障。
