# B 模块 CARE 数据核验记录

## 1. 核验范围

本次核验使用 CARE to Compare Version 6 的 Wind Farm A：

`E:\CARE_To_Compare\CARE_To_Compare\Wind Farm A`

只读取原始数据，没有修改原始文件。

## 2. 已确认的数据结构

- Wind Farm A 共 22 个数据集文件。
- 每个数据集对应一个事件样本，文件名就是 `event_id`。
- `event_info.csv` 使用分号 `;` 分隔，不是逗号分隔。
- `feature_description.csv` 使用分号 `;` 分隔。
- 数据集 51 的形状为 54,436 行、86 列。
- 数据采样间隔为 10 分钟。
- 数据集 51 的风机为 `asset_id = 21`。
- 数据集 51 只有 2 个缺失值，分别位于 `sensor_22_avg` 和 `sensor_14_avg`。
- 数据集 51 的 `train_test` 包含 `train` 和 `prediction` 两部分。

## 3. 适合作为第一个案例的事件

事件 51：

- 事件类型：`anomaly`
- 风机：`asset = 21`
- 事件描述：`Gearbox bearings damaged`
- 事件开始：`2023-10-06 01:30:00`
- 事件结束：`2023-10-17 16:10:00`
- 事件区间 ID：`52331` 到 `54003`

数据集 51 的 prediction 区间是 `2023-10-04 01:30:00` 到 `2023-10-20 16:10:00`，因此它同时包含事件前、事件中和事件后的数据。这个结构适合先做“事件前异常趋势检测”，但必须明确区分训练段、预警段和事件段，不能把事件发生后的数据用于提前预警特征。

## 4. 已确认的工程传感器映射

Wind Farm A 的字段说明可以支持具体工程解释。例如：

- `sensor_11_avg`：高速轴齿轮箱轴承温度
- `sensor_12_avg`：齿轮箱油温
- `sensor_13_avg`：发电机驱动端轴承温度
- `sensor_14_avg`：发电机非驱动端轴承温度
- `sensor_18_avg`：发电机转速
- `sensor_52_avg`：转子转速
- `power_29_avg`：可能的电网有功功率
- `power_30_avg`：电网功率
- `wind_speed_3_avg`：风速

这些字段可以用于建立“齿轮箱轴承损伤”案例的状态特征，但模型输入仍需经过缺失值、异常值、工况和统计量质量检查。

## 5. 第一版建模边界

第一版不做 RUL、深度学习或复杂优化，先完成可复现 baseline：

1. 只使用 Wind Farm A 的 `average` 信号作为主输入。
2. 先以事件 51 作为验证案例，不把所有故障类型混在一起。
3. 训练基准使用事件开始前的历史 `train` 数据。
4. 采用滚动统计、变化率、相对基线偏差等可解释特征。
5. 输出异常分数、健康指数和预警等级。
6. 用事件开始时间检查提前预警时间。
7. 任何成本、维修时长和资源数量都必须标记为假设或仿真，不写成真实数据。

## 6. 统一输出目标

后续 `inference.py` 应输出以下结构：

```json
{
  "turbine_id": "21",
  "component_id": "WT21_COMPONENT_GBX_BEARING",
  "timestamp": "2023-10-06T01:30:00",
  "health_index": 0.0,
  "anomaly_score": 0.0,
  "failure_risk": 0.0,
  "warning_level": "NORMAL",
  "model_version": "v0.1.0"
}
```

这里的 `component_id` 是项目内部稳定 ID；只有在团队确认接口后，前端才使用它。`failure_risk` 在第一版应被称为风险评分，不能直接宣称为经过校准的真实故障概率。
