# A D 维护规则确认清单

## 当前状态

第一版决策器中的阈值与资源条件用于联调，当前状态为 `ASSUMED`，尚未构成真实风场标准或比赛结论。

| 项目 | 当前暂定值 | 状态 | 需要确认的问题 |
| --- | --- | --- | --- |
| 中风险阈值 | `failure_risk >= 0.45` | 待确认 | 是否有模型验证、文献或工程规则支撑 |
| 高风险阈值 | `failure_risk >= 0.75` | 待确认 | 是否经过概率校准，能否称为风险概率 |
| 高风险动作 | 安排维护 | 待确认 | 是否应先安排检查，什么条件允许直接维护 |
| 中风险动作 | 安排检查 | 待确认 | 检查的工程内容和触发条件是什么 |
| 人员约束 | 可用或不可用 | 待细化 | 人员数量、技能和工时是否需要进入决策 |
| 维护窗口 | 可用或不可用 | 待细化 | 天气、风速和作业时间如何定义 |
| 重新规划 | 条件不足时触发 | 待确认 | 哪些变化必须重新生成方案 |

## A 需要提供

- 第一版允许使用的维护动作名称及工程含义。
- 阈值依据，或确认暂时仅作为仿真假设。
- 人员、工时、备件、天气窗口和停机约束的最小表达方式。
- CARE 数据能够支持的工程表述边界。
- 答辩时真实数据、派生结果、仿真情景和假设参数的统一口径。

## D 收到确认后的动作

- 更新阈值和规则实现。
- 为规则增加版本号并记录变更依据。
- 补充边界条件测试。
- 更新接口文档和联调样例。
- 重新运行本地测试和 GitHub Actions。

在 A 确认前，代码中的 `0.45` 和 `0.75` 只能作为 P0 联调阈值使用。
